## 1. What we are building

A **reading tool for tokenized stocks**, not a trading dashboard.

The Seeker's built-in wallet already has a "Stocks" tab and already sells xStocks. Every wallet that lists xStocks shows a ticker and a price and nothing else. PlainTicker's engine already produces SEC-grade fundamental classification for US equities. This app puts that classification on the phone, next to the swap that the wallet already offers — so the buy button is a convenience and **the analysis is the product**.

Positioning line, from PlainTicker's own DESIGN.md: *"reading-tool feel, not trading-dashboard."*

## 2. Decisions taken (do not re-litigate)

| Decision | Why |
|---|---|
| **Seeker-only** | Seed Vault Wallet's measured capabilities are the whole matrix. No Phantom/Backpack paths, no wallet picker in production. |
| **Mainnet** | xStocks and Jupiter are mainnet-only. `SUBMIT_SWAPS` build flag guards the one call that moves money. |
| **No geo-gating** | Accepted knowingly by the founder. Exposure is reduced with wording, disclaimers, a one-time self-certification, and no per-trade fees — never by blocking the button. |
| **No buy/sell verbs anywhere** | PlainTicker's own hard rule, reached after backtests showed the composite anti-predictive. Render `axes` + `fscore` + `composite_percentile`; never surface `verdict.label_en`. |
| **Phase-3 = 10 tickers**, then scale | Coverage is a CIK-map data-entry task, not engineering. Start at 10, reassess. |
| **Free in the hackathon build** | No judging criterion rewards a paywall; a wall in the demo hurts Completion. |
| **English-only UI** | Aligns with PlainTicker's EN-first pivot; UK locale stays on the web product. |
| **Design system = PlainTicker DESIGN.md** | Geist Sans/Mono, warm paper `#F5F2EA`, ink stack, OKLCH tones. Kill Material You `dynamicColor`. |

## 5. Architecture

```
Seeker (Kotlin / Compose / MWA 2.2.0)
├── PlainTicker  https://www.plainticker.com/api/v1
│     /summary            one call → the list (health-filtered)      [NEW]
│     /{TICKER}           full classification payload (v1.1)
│     /portfolio/{pubkey} Token-2022 balances × multiplier × price    [NEW, RPC proxy]
│     /entitlement        wallet-bound Pro (post-hackathon)           [NEW]
├── xStocks      https://api.xstocks.fi/api/v2/public   catalog, price, PoR, multiplier
└── Jupiter      https://api.jup.ag/swap/v2              /order → signTransactions → /execute
```

- **No RPC key ships in the APK** (repo goes public). Portfolio and mint reads go through PlainTicker, which also applies the Token-2022 multiplier consistently.
- **MWA identity** = `https://www.plainticker.com` with `/.well-known/assetlinks.json` served by the Next.js app. Replaces the `yourdapp.com` placeholder.
- **Wallet-bound entitlement** maps onto PlainTicker's existing next-auth tables so a web subscriber gets mobile Pro and vice versa.
- **PlainTicker repo rules apply to any change there:** read `.gstack/ceo-plans/2026-05-01-*.md` and `DESIGN.md` first; import from leaf modules, never the `lib/data/tickers` barrel; route work through `/plan-eng-review` → `/review` → `/ship`.

## 7. Monetization (post-hackathon; hackathon build is free)

Two tiers. **Free:** list, detail (score, axes, F-score), NAV premium, PoR, flags, swap — never locked. **Pro:** full narrative sections, method history, sector comparison, earnings alerts.

Entitlement is **wallet-bound**, not email-bound: server stores `pubkey → pro_until`, mapped onto PlainTicker's existing next-auth tables. Wallet control is proven by signing a server nonce with `signMessages` (SIWS is unavailable on Seed Vault Wallet); the server verifies ed25519 and issues a short-lived token checked on `/api/v1/*`.

Three ways to hold Pro:
1. **Stake ≥ N SKR** to any Guardian → Pro free. Read via the memcmp@41 query. Aligns with Solana Mobile's economics; this is the SKR-track feature and the monetization mechanism in one.
2. **Flat USDC payment** to a treasury with a memo; server verifies the transaction via RPC. Flat and independent of trading — that is the broker-dealer boundary.
3. **Seeker Genesis Token** holders get a trial or discount (Seeker-native).

**Never:** referral or per-swap "convenience" fees (transaction-based compensation on securities trades is the classic broker-dealer trigger, and it is cents at our volume anyway), ads, a card paywall on mobile.

**Where the real money is:** B2B licensing of the analysis API to wallets and DEX front-ends (Phantom, Solflare, Jupiter Mobile, Backpack) — every one of them shows a ticker and a price and nothing more. The hackathon is the sales demo. Keep `/api/v1` clean; write the integrator section in the README.

Unit economics: ~179 tickers × $0.025 × 8 refreshes/month ≈ $9/month LLM. One or two Pro subscribers cover the engine.

## 8. SKR bonus track — decide at the Sep 24 checkpoint

- **4 hd available → curation weighted by staked SKR.** Unserved xStock detail gets "Vote to cover next"; signed nonce proves the wallet; server weights the vote by staked principal; a "Next up" strip shows the top-weighted tickers; the prewarm run resolves the winner's CIK and covers it. Closes a real loop (vote → analysis appears). Matches Solana Mobile's own "SKR powers curation" language.
- **2 hd available → stake-to-unlock with a soft lock.** Read stake, show "Your stake: 31,209 SKR — Pro unlocked"; for non-stakers lock only a non-essential section with "free during the hackathon". Never lock the core one-pager. Client-side gating is bypassable by a modified APK — say so in the README.
- **< 2 hd → skip the track.** A half-shipped SKR feature costs more in Completion than $10k is worth.

Default recommendation: **stake-to-unlock first** (unifies monetization and the SKR track, demos on the founder's own wallet), curation as a second layer if time remains.

Transparently gimmicky — do not build: SKR rewards for coverage requests (the "distribute SKR across an existing user base" pattern Solana Mobile rejects, and farmable); SKR as merely one more payment checkbox; Seeker-only features gated on the spoofable `Build.MODEL`.

## 9. Build vs fake

**Must be real:** swap execution and its result (a landed signature or an error — never a success state without a transaction); every analysis payload (no canned one-pagers; SPY/QQQ/GLD stay analysis-less); PoR numbers; Jupiter quotes and NAV premium; portfolio balances; staked-SKR read; freshness (`age_days` displayed, never hidden); the video's core flow (speed-ups labeled).

**Honest fixtures:** a bundled snapshot of the 737-asset catalog (symbol, name, mint, underlying) as cold-start fallback with background refresh; the NYSE holiday calendar; sector labels; the static "how xStocks work" explainer (the extension set is identical across mints); the deterministic verdict→score mapping; a pre-funded demo wallet whose positions were actually bought; a manually triggered prewarm before the video (the real pipeline, invoked early).

**Grey area, decided:** the submitted APK ships with `SUBMIT_SWAPS` on. If the flag is ever off on screen, the UI must say "not submitted".

## 10. Top five remaining failure modes

1. **A demo ticker goes stale or 503 on judging day** (cron burst vs AlphaVantage 25/day). Guard: `/summary` health filter hides it automatically; run the health script + manual prewarm the morning of recording and of submission.
2. **Upstream drift** — a Seed Vault Wallet update, a Jupiter keyless change, xStocks tightening the UA rule. Guard: pin the Jupiter key; read `getCapabilities` at runtime; record the video Oct 2, not Oct 6.
3. **Judge's device has no USDC/SOL or is not a Seeker.** Guard: accept SOL as input; exact shortfall message; the app is fully useful at zero balance; the video carries the swap proof.
4. **Rate limits under judging load** (60 req/min per IP behind carrier NAT). Guard: one `/summary` call per list load; bundled catalog fallback; 30 s price cache; ≥2 s debounce on quote preview.
5. **The machine.** Guard: CI builds only; push hourly; keystore and credentials off-machine tonight; `/checkpoint` at end of every day.
