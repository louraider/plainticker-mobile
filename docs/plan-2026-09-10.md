## 1. What we are building

A **reading tool for tokenized stocks**, not a trading dashboard.

The Seeker's built-in wallet already has a "Stocks" tab and already sells xStocks. Every wallet that lists xStocks shows a ticker and a price and nothing else. PlainTicker's engine already produces SEC-grade fundamental classification for US equities. This app puts a **trust layer** nobody shows (is this token really backed, at NAV, and what can the issuer do to it) and that classification on the phone, next to the swap the wallet already offers. The buy button is a convenience; **the analysis and the trust layer are the product**.

Positioning line, from PlainTicker's own DESIGN.md: *"reading-tool feel, not trading-dashboard."* Pitch line: *"the layer under your Stocks tab."*

## 3. What is already proven (verified, not assumed)

- **A real mainnet swap landed from the Seeker** at slot 445899686 (signature held privately, shown in the video from the demo wallet): 5 USDC → 0.01366647 TSLAx. `/order` 593 ms · wallet round-trip 14.4 s · `/execute` 1.0 s · total 16.1 s.
- **Seed Vault Wallet capabilities** (mainnet): `solana:signTransactions` **present** (the sign-only path Jupiter's co-signed transactions need); `signInWithSolana` **absent** (use a self-signed nonce over `signMessages`); tx versions `legacy, 0`; 20 tx / 20 msg per request. `getCapabilities` lists *optional* features only — mandatory ones never appear.
- **Routing:** liquid names route via **Metis** (`gasless: false`, user pays ~26k lamports, no `expireAt`, no maker last-look). Illiquid names route via JupiterZ RFQ (`gasless: true`, ~55 s window). Treat a missing `expireAt` as "no expiry". All-in cost swung 0.08% → 1.44% on the same pair within 15 minutes in extended hours — surface cost and liquidity per quote.
- **Jupiter Price v3** (`GET https://api.jup.ag/price/v3?ids=<mints>`, keyless, batched) returns `usdPrice`, `liquidity`, `priceChange24h` and, for xStocks, `stockData.price` (underlying reference). NAV premium = `(usdPrice − stockData.price) / stockData.price`. Verified: TSLAx −0.093%, AAPLx +0.023%. `stockData` is **nullable** (XRXx lacks it).
- **xStocks public API** (`https://api.xstocks.fi/api/v2/public/*`, no key, browser UA required): 737 assets with a Solana mint; `proof-of-reserves`, `multiplier`, `corporate-actions`, and `trading.openNow / currentPeriod / nextChangeAt`. `/trades/*` is institutional — not for us.
- **PlainTicker `/api/v1/{TICKER}`** at `https://www.plainticker.com`: no auth, 60 req/min per IP, 169 served tickers, **149** with a live xStock. Foreign 20-F filers (TSM, ASML) return 200 with SEC-derived fields null — render as absent-and-explained.
- **`leaderboard_snapshot`** already holds `ticker, fscore, composite, setupScore, sector, actionTone, computedAt` per ticker, upserted by the prewarm cron — the list's data source.
- **SKR staking is readable without an IDL:** `getProgramAccounts SKRskrmtL83pcL4YqLWt6iPefDqwXQWHSw9S9vz94BZ`, `memcmp` offset **41** = wallet, `dataSlice` 105/8 = principal (6 dp). Verified against a real staked position. The wallet app shows principal + accrued rewards, so the numbers differ by design.
- **Token-2022:** xStock mints carry `scaledUiAmountConfig` (multiplier 1 today, changes on splits — always apply it), `permanentDelegate`, `pausableConfig`, `defaultAccountState: initialized`, `transferHook` with a null program. **These are read via `getAccountInfo` with `encoding: jsonParsed` — the RPC node decodes the TLV; the app parses JSON.** Raw byte offsets are used only for the SKR staking account, a fixed-layout custom-program struct.
- **Machine:** the dev box has a degrading i7-14700K. Mitigations (turbo off, Gradle at 8 workers) held through six builds; CI is the source of truth for submitted APKs.

├── PlainTicker  https://www.plainticker.com/api/v1

## 7. Monetization (post-hackathon; hackathon build is free)

Two tiers. **Free:** list, detail (trust layer + score/axes/F-score), NAV premium, PoR, issuer controls, swap — never locked. **Pro:** full narrative sections, method history, sector comparison, earnings alerts.

Entitlement is **wallet-bound**: server stores `pubkey → pro_until` on PlainTicker's existing next-auth tables (`account.provider = "solana-wallet"`; `userSubscription.paymentProvider` gains `skr-stake` / `usdc-transfer` via a CHECK-constraint migration). Wallet control is proven by signing a server nonce with `signMessages`; the server verifies ed25519 and issues a short-lived token.

Three ways to hold Pro: **stake ≥ N SKR** (read via the forwarder) → Pro free; **flat USDC payment** to a treasury with a memo, verified via RPC — flat and independent of trading, which is the broker-dealer boundary; **Seeker Genesis Token** holders get a trial. **Never:** referral or per-swap fees, ads, a card paywall on mobile.

**Where the real money is:** B2B licensing of the analysis API to wallets and DEX front-ends — every one of them shows a ticker and a price and nothing more. The hackathon is the sales demo; the README's integrator section is the pitch. Unit economics: ~179 tickers × $0.025 × 8 refreshes/month ≈ $9/month LLM.

### Pass 3 — User journey (4/10 → 9/10)

- **First five seconds.** The wordmark `PLAINTICKER` sits in the header's left meta on every screen — Geist Mono 11 uppercase tracked, the same style as section numbers; present in the first frame, never louder than the data. Onboarding = "PlainTicker" Sans 28 · "Tokenized stocks, read before you swap." · three sentences (what it reads from the chain; what the fundamentals are; "Not a price forecast. Not investment advice.") · self-certification checkbox · Continue enabled only when checked. The list renders beneath a scrim so the first frame is content, not a form.
- **The wallet round-trip (measured 12.7–14.4 s).** The sheet shows three honest phases in mono with real elapsed time: "Confirm in Wallet · 9 s" → "Landing · 3 s" → receipt. No fake progress bar, no spinner. On **Landed**: one light haptic (`HapticFeedbackType.Confirm`) and the receipt fades in over 200 ms per DESIGN.md motion. On **Cancelled**: no haptic, neutral copy, sheet stays.
- **The return.** A notification deep-links to exactly what it named: "AAPLx reports in 3 days" → AAPLx Detail; the digest → Watchlist tab; one nav route shared with the Today stripe. Today stripe copy when fresh: "Today · 2 watched · 1 premium moved · next report AAPLx in 3 d"; when the worker has not run in 24 h+: "checked 26 h ago · tap to refresh"; **hidden entirely when nothing is watched.**

Storyboard (what the user feels, and what supports it): 1 opens → a promise with a checkbox under it, product visible behind (7A) · 2 list → "this knows something" (3A) · 3 TSLAx → "it's reading the chain right now" (2A live signature) · 4 fundamentals → "and the company is… fair" · 5 Swap after METHOD → informed, not pushed (4A) · 6 wallet → alive, counted (8A) · 7 landed → relief, one haptic, a receipt (8A) · 8 next day → the notification opens what it named (9A) · 9 week two → Today stripe as a routine (9A) · 10 five years → the wordmark is the thing remembered (7A).

### Pass 4 — AI-slop risk (7/10 → 9/10)

- **One pulse per screen.** The trust layer's 6dp positive dot is the only motion in the first viewport; the header's "DATA UPDATED …" is static mono meta (the web Hero's asOf pulse is not ported). Numbered `SectionHead` labels stay as the wayfinding spine — six on Detail, two on List — and the em dash appears **only** inside `NN — LABEL`; body copy, notifications and empty states use periods and middle dots.
- **UI copy rule (T7–T12), enforced by a strings.xml lint in the same test as the BUY/SELL/HOLD invariant:** sentence case everywhere except mono meta; buttons are verb + object ("Swap USDC → TSLAx", "Watch AAPLx", "Connect wallet"; the onboarding button is "Read the list", never "Get started" or a bare "Continue"); banned words: seamless, powerful, unlock, empower, journey, insights, supercharge, effortless, all-in-one, welcome to; no exclamation marks; no emoji; no first-person-plural hype. The interface speaks in the same calm register as the analysis.

### Pass 6 — Responsive & accessibility (4/10 → 9/10)

- **Android accessibility spec (T7 components, T8–T12 screens; the web ARIA section of DESIGN.md translated to TalkBack):**

- **Responsive scope: portrait locked, one column, 360–430dp.** `android:screenOrientation="portrait"` on the single Activity (rotation can no longer recreate the Activity mid-signing). Layout is a scrolling column tuned for the Seeker's ~412dp; the header row autosizes down to 0.85× so `TSLAx · $1,234.56` fits a 360dp phone on one line. Edge-to-edge (enforced on Android 15+): header takes the status-bar inset, the Swap button and tab row take the navigation inset; no bottom bar to collide with gestures. No landscape, tablet or two-pane work; multi-window degrades to the same column. Preview set in T7: 360 · 412 · 412@1.3× font scale.
