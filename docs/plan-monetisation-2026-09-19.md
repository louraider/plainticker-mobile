Written 2026-09-19, ten days before the feature freeze (end of 29 September). Nothing below is built unless section 0 says so.

## 0. What is true today

- No payment rail. `CheckoutPayCta` links to a route that does not exist; `subscription_pending` is never written; `payment_provider` is checked against `wayforpay`, `manual`, `stripe` (`lib/db/schema.ts` 447 to 450).

- The List is one column: about 157 analyzed rows, then about 672 price-only rows with the Next up strip in front (`ListScreen.kt`). Sector is in `/summary` (`lib/leaderboard/summary.ts` 34).

## 1. Decisions

### 1.1 The gate: depth, on every ticker page

**Decision.** Every served page stays open and indexable. Four blocks lock: 04 The read, 06 Sector table, 07 Method history, 09 What to check next. Everything `/api/v1` already carries stays free, so the app's feed is untouched by construction. The seven freshest analyses, by `computed_at` in `leaderboard_snapshot`, are fully open, replacing the fixed five. The coverage screen is unchanged in every flag state.

**Why.** Traffic is organic, and the marketing plan names the cited edge as the interpretation layer, classification plus a public rule (`docs/marketing/2026-07-10-marketing-plan-v2.md`, lines 10 to 20). A page that answers with a door teaches crawlers and assistants to stop asking; one that keeps its classification and sector context answers them and locks the prose. The founder decided this on 2026-09-13. A judge opening any ticker meets a full page, not a wall.

| Block | State | A locked block shows |
|---|---|---|
| Hero, blurb, verdict band, quick view, 01 Snapshot, 02 F-Score, 03 Numbers, 05 Earnings, 08 Expectations, sources, disclaimer | Free | |
| 04 The read | Locked | Section head, the narrative's first sentence as plain text, one calm line naming the price and the stake threshold with a link to `/upgrade`. The rest is not in the HTML. |
| 06 Sector table, 07 Method history, 09 What to check next | Locked | The company's own row; the latest classification row; the three step titles. |

Paywalled-content structured data (`isAccessibleForFree: false` with `hasPart` selectors) declares the peeks so they are not read as cloaking. No new `noindex`. The sticky banner is retired; the inline line under each locked block is the only ask.

### 1.2 Entitlement: the memo transaction, no auth surface

**Decision.** A wallet becomes a subscriber the way it becomes a voter: by signing a transaction whose memo the tally reads.

| Memo | Transaction | The tally records |
|---|---|---|
| `PT-VOTE:<TICKER>` | 0-lamport transfer to the collector | a vote (exists) |
| `PT-LINK:<code>` | 0-lamport transfer to the collector | `wallet_link(wallet, code)`: a web-issued code binds the wallet to a signed-in user; an app-minted code binds it to that device |
| `PT-PASS:<code>` | 12.00 USDC or USDT to the treasury's token account, treasury owner as a reference key | `wallet_pass(wallet, until = block time + 30 days)`, plus the same link |

The code is random, generated by whoever starts the flow; web codes expire in 15 minutes. The app keeps its code on the device and writes only the hash into the memo; reads of locked content carry the code in a header and the server hashes it to find the wallet. The memo is public and the preimage is not, so a signed transaction mints a bearer credential and no signature verification, nonce store or token lifetime enters the web repository. The cost is the wait for the tally, so `POST /api/v1/pass/confirm {signature}` verifies one transaction on demand with the tally's existing verifier.

**Stake threshold: 10,000 SKR staked principal**, read server-side through `readStakedPrincipal` with its bound, cached ten minutes, never stored. From the 2026-09-13 scan of 46,436 non-zero stakes (`docs/skr-plan-2026-09-13.md`): 10,000 is both p70 and p75 because 6,189 wallets sit on it exactly, and 36.6 percent of stakers clear it. Re-measured quarterly against the distribution, not price. The demo wallet does not clear it; a demo of premium shows the USDC path.

**Price: $12 for 30 days, paid once.** The founder's 2026-09-13 correction set $10 to $12 against comparables at $10 to $30; 30 days is the `cycleDays` already in `pricing.ts`. No renewal, so no cancellation flow and no dunning.

**How web and app agree about one person.** The wallet is the join key. Web tier for a signed-in user = an active `user_subscription` row, or a linked wallet with an unexpired pass or a stake at the threshold. App entitlement = `GET /api/v1/entitlement` with the device code: the wallet's pass, its stake, or a subscription of the linked user; the response carries `{pro, source, until}` and never a user identifier. Wallet only: entitled in the app at once, on the web after an email sign-in and a link code from `/account`. Email only: entitled on the web by a manual grant, in the app after linking a wallet.

### 1.3 Payment rail: USDC on Solana, no card yet

**Decision.** USDC, with USDT accepted at the same amount, through a Solana Pay transfer request: the web shows a QR and a copyable link carrying amount, mint, memo and reference key, and any Solana Pay wallet scans it. From the app, after the hackathon, the server builds the transfer like a vote and the app signs. The server never signs. The treasury is a fresh keypair the founder keeps offline (`PAY_TREASURY_PUBKEY`), not the collector, which the README documents as read-only; the tally refuses token transfers to the collector and walks both addresses with two cursor rows.

**No card.** WayForPay or Stripe means merchant onboarding, a webhook, refunds, chargebacks and a support queue nobody runs. Crypto only, until `subscription_interest` plus USDC conversions show demand.

**Check constraint and refunds.** Passes live in their own `wallet_pass` table, so `user_subscription_provider_check` is not widened and `manual` keeps working for grants. Refunds: none; a pass is a transfer on a public chain and the page says so above the QR. A wrong amount or unreadable memo lands in `pass_unmatched` with its signature and the founder resolves it with a manual grant. That is the support path.

### 1.4 Voting rounds: weekly, closing Monday 00:00 UTC

**Decision.** A round is one week, Monday 00:00 UTC to Monday 00:00 UTC. Round 1 opened 2026-09-15, contains the 18 September vote and closes 22 September. The first tally after the boundary writes the winner, the largest summed weight among tickers still uncovered with ties by ticker order, and opens the next round. Votes are assigned by block time. One wallet counts once per ticker per round and may vote for several tickers.

**Why weekly.** A winner's analysis appears only after the founder adds one line to `TICKER_TO_CIK`, deploys, and the prewarm cron runs, which is Wednesday and Sunday at 03:00 UTC, so no shorter round can keep its promise. A Monday close leaves two weekdays for the line and the deploy, and Wednesday's prewarm publishes. The twenty minutes a vote can take to appear (tally ten, edge five, app five) is noise against a week and most of a day. Model spend is about $0.025 a winner; the founder's hand is the constraint until `S4` removes it.

**What a reader sees.** During a round: the round number, when it closes, the leaders with weight and voters, and the wallet's own votes from a local receipt store. For 24 hours after a close the announcement sits above the fresh leaders: winner, weight, voters, "analysis expected Wednesday". Then the winner stays under "Last round" as pending, published (linking into its Detail, the loop closing), or could not be covered with the reason, and the runner-up is covered. The last four rounds are listed, so a missed round is readable. Rounds are back to back, so no between-rounds state exists. The landed sheet says: counted within about twenty minutes.

**Contract.** `next-up` gains `round {id, opens_at, closes_at}` and `previous {id, winner, weight, voters, closed_at, status}`, additive and scoped to the current round; the shipped app ignores unknown keys.

### 1.5 The app: four tabs, the ballot leaves the List

**Decision.** Tabs become List, Vote, Portfolio, Watchlist.

**List** carries analyzed tokens only, chaptered by sector: a heading per sector with its count, sectors ordered by count, rows by composite within; search spans both sets, and an uncovered hit opens its Detail, where the vote action already is. Removing the 672 price-only rows takes 81 percent of the rows off the screen; chaptering the remaining 157 by sector matches the method's frame, since every score is against a sector.

**Vote** is the ballot and its explanation: the round header; short paragraphs on what this is (coverage is the scarce thing), what it is for (staked SKR allocates it) and how it works (a memo transaction, weight read on-chain, one wallet once per ticker per round, the sentence about large stakes); the leaders; the wallet's votes; the last rounds; then every token without analysis, with a search field and the one-word Vote action into the existing sheet. Detail and the Today strip are unchanged before the freeze.

## 2. Sequence and the minimum credible slice

Web before app wherever the app depends on the web. The web repository has no freeze, but the round fields must be live by 26 September to be in the frozen app.

**Before the freeze:** the List's shape, the Vote tab, and rounds on the server: 26 hours in a window that also carries the 24 September checkpoint, the device matrix and the video rehearsal.

**Premium cannot land credibly before the freeze.** The web slice is five tasks and a canary, and a half-built one in front of judges is worse than none. It lands from 9 October, in order; the app's Pro block follows the web canary. Premium is not in the video, and the flag is not flipped between 1 and 8 October.

**Minimum credible slice if the tripwire fires:** `A1` and `A2` reading the continuous `next-up` with no round header, since the header is drawn only when the server sends `round`; the screen never describes rounds the server does not run.

## 4. Risks

- **Live site.** Flipping the flag before W1 to W3 sends uncovered tickers to a Ukrainian $3 block and exposes UK-only pages to EN readers. Guard: the flag stays off until W4; `monetization-flag-off.test.ts` keeps the default; W2 asserts flag-off output is byte-identical.
- **Production database.** Migrations hit production directly (one Neon); 0024 replaces a unique constraint on a live table, and a NULL `round_id` would let duplicates through. Guard: operator-applied only; backfill in the same migration before the constraint; the tally is idempotent.
- **The app's unauthenticated feed.** `/api/v1/{ticker}` and `/summary` are touched by no task; `next-up` changes are additive.
- **The demo path.** The video's SKR segment is blocked on the List's strip, which A1 removes. Guard: A4 re-blocks it on the Vote tab before 26 September, the go or no-go date in the script.
- **SEO and cost.** Peeks could read as cloaking or trigger model spend, and the meta description comes from the narrative. Guard: only the peek is in the HTML, read from the cached payload; structured data declares the locked parts; the description stays a summary; Search Console watched two weeks; rollback is the flag.
- **The weekly hand.** A winner needs a founder's line and a deploy every week until S4. Guard: O1 names the day; the screen shows "pending" rather than a promise.
- **Pinned test.** `coverage-zero-outbound.test.ts` pins the exact gate call text in `page.tsx`. Guard: W2 updates the anchors in the same pull request.
